# Вектор-06Ц — Полная документация по процессору, ASM и машинному коду

> Документация предназначена для написания корректного ассемблерного и машинного кода под Вектор-06Ц.  
> Основана на официальных и проверенных источниках (техническое описание, «Секреты Вектора» Лебедева А.З., эмуляторы, тайминги).

## 1. Общие сведения о компьютере

| Параметр              | Значение                                      |
|-----------------------|-----------------------------------------------|
| Процессор             | **КР580ВМ80А** (клон Intel 8080A)             |
| Тактовая частота      | **3 МГц** (заводской разгон, штатно до 2,5 МГц) |
| Разрядность           | 8 бит данных, 16 бит адреса                   |
| ОЗУ                   | 64 КБ                                         |
| ПЗУ                   | 0,5–2 КБ (загрузчик)                          |
| Видео                 | 256×256 16 цветов / 512×256 4 цвета           |
| Звук                  | КР580ВИ53 (3 канала + шум)                    |
| Прерывания            | Аппаратное VBlank → RST 7 (адрес 0038h)       |

**Важно:** из-за видеоконтроллера каждый машинный цикл растягивается.  
Реальные тайминги команд на Векторе **отличаются** от чистого 8080.

## 3. Карта памяти Вектор-06Ц

```
0000h – 00FFh   — область векторов прерываний и перезапуска
0100h – ...     — обычно начало пользовательских программ (.ROM)
8000h – BFFFh   — видеоОЗУ (в зависимости от режима)
C000h – FFFFh   — видеоОЗУ / пользовательская память
```

### Важные адреса

| Адрес   | Назначение                                      |
|---------|-------------------------------------------------|
| 0000h   | Вектор сброса (обычно JMP на программу)         |
| 0038h   | Вектор прерывания VBlank (RST 7)                |
| 0100h   | Стандартная точка входа для .ROM-файлов         |

### Почему большинство программ начинаются с адреса 0100h?

Это **не случайность** и не «магия» Вектора. Причины накладываются друг на друга:

1. **Наследие CP/M и МикроДОС**  
   В операционной системе CP/M (и её советском клоне МикроДОС) все пользовательские программы формата `.COM` **всегда** загружаются и запускаются с адреса **0100h**.  
   Область `0000h–00FFh` в CP/M зарезервирована под:
   - векторы перезапуска и прерываний
   - System Control Block
   - Zero Page (служебная область)
   - часть BDOS/BIOS  
   Вектор-06Ц широко использовал МикроДОС/CP/M, поэтому стандарт автоматически перешёл и на «голые» ROM-программы.

2. **Область векторов процессора 8080 / КР580ВМ80А**  
   На этом процессоре:
   - `0000h` — вектор сброса (после нажатия БЛК+СБР или холодного старта)
   - `0038h` — вектор RST 7 (кадровое прерывание VBlank на Векторе)  
   Если программа начинается прямо с `0000h`, она перезаписывает эти критические векторы. При любом сбросе или прерывании управление уходит в мусор.  
   Поэтому корректные программы оставляют `0000–00FFh` свободной и **сами** прописывают туда `JMP` на свой код.

3. **Формат файлов .ROM**  
   В экосистеме Вектора файл `.rom` — это дамп памяти, **начинающийся с адреса 0100h**.  
   Все основные эмуляторы (Virtual Vector, Emu80, v06x, MiSTer и др.) загружают `.rom` именно по адресу `0x0100` и запускают выполнение с него.  
   Если сделать `ORG 0000h`, эмулятор всё равно положит данные с `0100h`, программа окажется сдвинутой на 256 байт и не заработает.

4. **Историческая традиция**  
   Монитор-отладчик, Редактор-Ассемблер, большинство игр и утилит изначально начинались с `0100h`. Это стало стандартом де-факто.

**Типичная ошибка нейросетей и начинающих:**

```asm
ORG 0000h          ; ← неправильно для Вектора!
; код...
```

Такой ROM:
- перезаписывает векторы сброса и прерывания;
- в эмуляторах загружается со сдвигом;
- на реальной машине при БЛК+СБР уходит в неизвестность;
- часто конфликтует с монитором/загрузчиком.

**Правильный минимальный шаблон:**

```asm
        ORG  0100h

Start:  DI
        MVI  A,0C3h         ; код команды JMP
        STA  0000h
        STA  0038h
        LXI  H,Main         ; адрес вашей основной программы
        SHLD 0001h
        LXI  H,IntHandler   ; адрес обработчика прерывания
        SHLD 0039h
        XRA  A
        OUT  10h            ; отключить квазидиск (для совместимости)
        EI
        JMP  Main
```

## 5. Порты ввода-вывода Вектор-06Ц

### 5.1. Основные порты (стандартная конфигурация)

| Порт  | Направление | Назначение                                      |
|-------|-------------|-------------------------------------------------|
| 00h   | W           | Управляющее слово КР580ВВ55 (клавиатура/магнитофон) |
| 01h   | R/W         | Порт C ВВ55 (клавиатура, магнитофон, скроллинг) |
| 02h   | R/W         | Порт B ВВ55 (адрес палитры + опрос клавиатуры)  |
| 03h   | R/W         | Порт A ВВ55 (опрос клавиатуры)                  |
| 04h   | W           | Управляющее слово второго ВВ55 (порт ПУ)        |
| 05–07h| R/W         | Порты параллельного интерфейса «ПУ»             |
| 08–0Bh| W           | КР580ВИ53 (таймер / звук)                       |
| 0Ch   | W           | Запись в палитру (цвет)                         |
| 0Eh/0Fh| R          | Джойстики (в некоторых конфигурациях)          |
| 10h   | W           | Управление квазидиском / ERAM                   |
| 14–15h| W           | AY-3-8910 (если установлен)                     |
| 18–1Ch| —           | Контроллер НГМД                                 |

### 5.2. Типичная инициализация портов

```asm
; Инициализация ВВ55 (порты 00-03)
        MVI  A,88h          ; A=вывод, B=вывод, C=ввод(верх)/вывод(низ)
        OUT  00h

; Или для клавиатуры + палитры:
; Порт 02 — адрес палитры (младшие 4 бита) + чтение столбцов клавиатуры
; Порт 03 — вывод строк матрицы клавиатуры
; Порт 0C — данные палитры
```

### 5.2.1. Опрос клавиатуры (полная документация)

#### Как устроена клавиатура

Клавиатура Вектора — **матрица 8×8** (основная часть) + несколько служебных клавиш.

| Порт  | Направление | Назначение                                      |
|-------|-------------|-------------------------------------------------|
| **03h** | Вывод     | Строки матрицы (подаём «0» на одну строку)     |
| **02h** | Ввод      | Столбцы матрицы (читаем состояние 8 клавиш)    |
| **01h** | Ввод      | Служебные клавиши (УС, СС, РУС/LAT и др.)      |

Принцип опроса (из «Секретов Вектора»):

1. На порт **03h** выдать маску, в которой только **один** бит = 0 (остальные = 1).
2. Прочитать порт **02h** — там будет состояние восьми клавиш этой строки (0 = нажата).
3. Повторить для всех 8 строк.

> Важно: опрос клавиатуры и запись палитры используют одни и те же порты 02h/03h. Поэтому их обычно делают **в обработчике прерывания VBlank**, чтобы не мешать изображению.

#### Полная таблица матрицы клавиатуры (8×8)

Строка выбирается записью маски в порт **03h** (активный уровень — 0).  
Столбцы читаются из порта **02h** (0 = клавиша нажата).

```
Строка  │ Маска 03h │ Бит7  Бит6  Бит5  Бит4  Бит3  Бит2  Бит1  Бит0
────────┼───────────┼────────────────────────────────────────────────
  0     │   FEh     │  ↓    →    ↑    ←   ЗАБ   ВК   ПС   TAB
  1     │   FDh     │  F5   F4   F3   F2   F1  АР2  СТР  ^\
  2     │   FBh     │  7    6    5    4    3    2    1    0
  3     │   F7h     │  /    .    =    ,    ;    :    9    8
  4     │   EFh     │  G    F    E    D    C    B    A    @
  5     │   DFh     │  O    N    M    L    K    J    I    H
  6     │   BFh     │  W    V    U    T    S    R    Q    P
  7     │   7Fh     │ SPC   ^    ]    \    [    Z    Y    X
```

**Пояснения к специальным клавишам строки 0 и 1:**

| Обозначение | Значение                          |
|-------------|-----------------------------------|
| ↓ → ↑ ←     | Курсоры (вниз, вправо, вверх, влево) |
| ЗАБ         | Забой (Backspace)                 |
| ВК          | Возврат каретки (Enter)           |
| ПС          | Перевод строки                    |
| TAB         | Табуляция                         |
| F1–F5       | Функциональные клавиши            |
| АР2         | АР2                               |
| СТР         | Строка (Home/Clear?)              |
| ^\          | Часто используется как служебная  |
| SPC         | Пробел                            |

#### Служебные клавиши (читаются через порт 01h)

Эти клавиши **не входят** в матрицу 8×8 и читаются отдельно:

| Клавиша   | Как читать (типично)          | Примечание                  |
|-----------|-------------------------------|-----------------------------|
| УС        | бит порта 01h                 | Управляющая (Ctrl)          |
| СС        | бит порта 01h                 | Сдвиг (Shift)               |
| РУС/ЛАТ   | бит 7 порта 01h (часто)       | Переключение раскладки      |
| БЛК       | аппаратная (вместе с СБР)     | Блокировка / сброс          |
| СБР       | аппаратная                    | Сброс                       |

> Точное расположение битов УС/СС/РУС/ЛАТ может немного отличаться на разных ревизиях (ёмкостная vs герконовая клавиатура). В играх обычно проверяют нужный бит маской.

#### Инициализация ВВ55 для клавиатуры

```asm
        MVI  A,8Ah          ; порт A (03) = вывод, порт B (02) = ввод,
        OUT  00h            ; порт C — смешанный
```

(значение 88h тоже часто используют, в зависимости от нужного режима порта C).

#### Простейший опрос одной строки (пример из Лебедева)

```asm
; Опрос первой линейки (курсоры, ВК, ПС, ЗБ, ТАБ и т.п.)
        MVI  A,0FEh         ; бит 0 = 0, остальные = 1
        OUT  03h
        IN   02h            ; читаем столбцы
        STA  KeyKod         ; 0FFh = ничего не нажато
                            ; иначе — битовая маска нажатых клавиш
```

#### Полное сканирование матрицы 8×8

```asm
; Результат: 8 байт в буфере KeyMatrix (по одному на строку)
; 0 = клавиша нажата

ScanKeyboard:
        LXI  H,KeyMatrix    ; буфер 8 байт
        MVI  B,0FEh         ; маска первой строки
        MVI  C,8            ; 8 строк
ScanLoop:
        MOV  A,B
        OUT  03h            ; выбрать строку
        IN   02h            ; прочитать столбцы
        MOV  M,A            ; сохранить
        INX  H
        MOV  A,B
        RLC                 ; сдвинуть маску на следующую строку
        MOV  B,A
        DCR  C
        JNZ  ScanLoop
        RET

KeyMatrix:  DS  8
```

#### Определение нажатия и отпускания (edge detection)

Чтобы ловить именно момент нажатия / отпускания, нужно сравнивать текущее состояние с предыдущим:

```asm
; PrevMatrix — предыдущее состояние (8 байт)
; KeyMatrix  — текущее

; Пример для одной строки (аналогично для всех):
        LDA  KeyMatrix
        MOV  B,A            ; текущее
        LDA  PrevMatrix
        XRA  B              ; изменившиеся биты
        ANA  B              ; только те, что стали 0 (нажатие)
        ; A теперь содержит биты только что нажатых клавиш

        ; Аналогично для отпускания:
        ; XRA + ANA с инверсией текущего
```

#### Служебные клавиши (порт 01h)

Через порт **01h** (старшие биты) обычно читаются:

- РУС/LAT
- УС (управляющая)
- СС (сдвиг)
- иногда другие

Пример:

```asm
        IN   01h
        ANI  80h            ; проверить бит РУС/LAT
        ; 0 = нажата, 1 = отжата (или наоборот — зависит от схемы)
```

#### Важные замечания

- Опрос лучше всего делать в **VBlank** (вместе с установкой палитры).
- Порт 02h используется и для палитры, и для клавиатуры → нельзя смешивать операции бездумно.
- На разных экземплярах (ёмкостная / герконовая клавиатура) поведение чуть отличается, но матричный принцип один.
- В играх часто делают упрощённый опрос только нужных клавиш (курсоры + огонь), а не всю матрицу.

#### Типичные ошибки

| Ошибка                                      | Почему плохо                              |
|---------------------------------------------|-------------------------------------------|
| Опрашивать клавиатуру вне VBlank            | Дёргается изображение / скроллинг         |
| Подавать «0» сразу на несколько строк       | Ложные срабатывания (ghosting)            |
| Не сохранять предыдущее состояние           | Невозможно отличить press от hold         |
| Забывать перенастраивать ВВ55               | Порты работают не так, как ожидается      |

### 5.3. Видеопамять и рисование (полная документация)

#### 5.3.1. Организация видеопамяти

Видеопамять Вектора состоит из **четырёх битовых плоскостей** по 8 КБ:

| Плоскость | Адресный диапазон | Бит в цвете пикселя |
|-----------|-------------------|---------------------|
| 0         | E000h–FFFFh       | бит 0 (младший)     |
| 1         | C000h–DFFFh       | бит 1               |
| 2         | A000h–BFFFh       | бит 2               |
| 3         | 8000h–9FFFh       | бит 3 (старший)     |

- В режиме **256×256 / 16 цветов** используются все 4 плоскости (32 КБ).
- В режиме **512×256 / 4 цвета** плоскости объединяются попарно.
- Неиспользуемые плоскости можно применять как обычную ОЗУ.

#### 5.3.2. Как устроен байт в плоскости (режим 256×256)

- Один байт = **8 горизонтальных пикселей**.
- Старший бит (бит 7) — самый левый пиксель в группе.
- Младший бит (бит 0) — самый правый.
- Байты идут **снизу вверх** внутри столбца шириной 8 пикселей.
- Следующий столбец начинается на +0100h.

Пример:
- `80FFh` — нижние 8 пикселей самого левого столбца плоскости 3.
- `8000h` — верхние 8 пикселей того же столбца.
- `81FFh` — нижние 8 пикселей следующего столбца.

#### 5.3.3. Вычисление адреса пикселя (256×256)

Для пикселя **(X, Y)**, X=0…255, Y=0…255 (Y=0 — верх экрана):

```
Столбец     = X / 8
Бит_в_байте = 7 − (X % 8)          ; старший бит = левый
Адрес       = 8000h + Столбец×100h + (255 − Y)
```

#### 5.3.4. Установка / сброс пикселя в одной плоскости

```asm
; HL = адрес в плоскости, C = маска бита
SetPixel:
        MOV  A,M
        ORA  C
        MOV  M,A
        RET

ResPixel:
        MOV  A,C
        CMA
        ANA  M
        MOV  M,A
        RET
```

Чтобы получить нужный цвет 0…15, операцию нужно выполнить во **всех используемых плоскостях** (бит 0 → плоскость 0, бит 1 → плоскость 1 и т.д.).

#### 5.3.5. Режим 512×256

Горизонтальное разрешение удваивается, количество цветов падает до 4.  
Плоскости объединяются попарно. Адресный расчёт сложнее.  
Для большинства игр предпочтительнее режим 256×256.

#### 5.3.6. Аппаратный вертикальный скроллинг

Управляется через порт **01h**. Значение 0…255 сдвигает изображение по вертикали.  
Очень дешёвый способ анимации фона.

#### 5.3.7. Типичные ошибки

| Ошибка                                      | Почему плохо / как правильно             |
|---------------------------------------------|------------------------------------------|
| Считать видеопамять линейным framebuffer    | Байты идут столбцами снизу вверх         |
| Забыть, что бит 7 = левый пиксель           | Картинка будет зеркальной                |
| Рисовать только в одну плоскость            | Получится не тот цвет                    |
| Портить плоскости, используемые под данные  | Конфликт с программой                    |
| Не учитывать, что Y=0 — верх экрана         | Перепутается верх/низ                    |

### 5.4. Палитра (полная документация)

#### 5.4.1. Как устроена палитра

Палитра Вектора — это небольшое статическое ОЗУ (обычно на двух К155РУ2) на 16 ячеек по 8 бит.

- Логический цвет пикселя (0…15) берётся из четырёх битовых плоскостей видеопамяти.
- Этот номер подаётся на адресные входы палитры.
- На выходе палитры получается физический цвет, который идёт на ЦАП.

**Формат физического цвета (1 байт):**

```
Биты:  7 6 | 5 4 3 | 2 1 0
       B B | G G G | R R R
```

- RRR — 3 бита красного (0…7)
- GGG — 3 бита зелёного (0…7)
- BB  — 2 бита синего (0…3)

Всего **256** возможных оттенков (8×8×4).

#### 5.4.2. Порты для работы с палитрой

| Порт  | Назначение                                      |
|-------|-------------------------------------------------|
| **02h** | Младшие 4 бита = номер ячейки палитры (0…15)   |
| **0Ch** | Данные — физический цвет (записывать сюда)     |
| 0Dh–0Fh | На некоторых машинах тоже работают как 0Ch     |

#### 5.4.3. Стандартная (безопасная) установка палитры

Рекомендуется делать **только во время обратного хода луча** (в обработчике прерывания VBlank / RST 7).

Классический надёжный способ (из «Секретов Вектора»):

```asm
; HL указывает на таблицу из 16 байт физических цветов
; (COLR0 … COLR15), начиная с последнего
SetPalette:
        MVI  A,88h          ; настройка ВВ55 (если ещё не сделана)
        OUT  00h
        MVI  E,0Fh          ; начинаем с цвета 15
        MVI  D,16           ; 16 цветов
PalLoop:
        MOV  A,E
        OUT  02h            ; номер ячейки палитры
        MOV  A,M            ; взять физический цвет
        OUT  0Ch            ; записать
        OUT  0Ch            ; повторить несколько раз
        OUT  0Ch            ; (на части машин запись «плохая»)
        OUT  0Ch
        DCX  H
        DCR  E
        DCR  D
        JNZ  PalLoop
        RET
```

> **Важно:** на многих экземплярах Вектора одна запись в `0Ch` может не сработать. Поэтому почти все старые программы пишут один и тот же байт 4–8 раз подряд.

#### 5.4.4. Цвет бордюра и фона

- Цвет бордюра задаётся одним из значений палитры (часто ячейка 15).
- В режиме с несколькими плоскостями «фон» — это цвет, соответствующий комбинации битов 0000.

#### 5.4.5. «Гонка луча» (racing the beam) и >16 цветов

Палитру **можно** менять **прямо во время формирования кадра** (не только в VBlank).

Это позволяет:

- Показывать **больше 16 цветов** одновременно на одном экране.
- Делать горизонтальные «полосы» с разными палитрами (мультиколор, raster bars).
- Создавать эффекты, похожие на copper Amiga / растровые эффекты C64.

**Самый известный пример** — тест, который показывает все 256 цветов Вектора на одном кадре (Целиков и др.). Палитра многократно перепрограммируется в течение одного кадра.

**Как это делается практически:**

1. В VBlank выставляют начальную палитру.
2. Ждут определённую строку (по таймеру или по счётчику строк).
3. Быстро меняют несколько (или все) ячеек палитры.
4. Повторяют на следующих строках.

**Ограничения и подводные камни:**

- Запись во время активного хода луча менее надёжна → обязательно несколько `OUT 0Ch`.
- Если менять слишком часто и не синхронизировано — появляются артефакты, мерцание, «грязь».
- На разных экземплярах Вектора (Кишинёв, другие заводы, .02) стабильность записи может отличаться.
- Самый безопасный и совместимый способ полной смены палитры — всё равно VBlank.

#### 5.4.6. Типичные ошибки

| Ошибка                                      | Последствия                          | Как правильно                     |
|---------------------------------------------|--------------------------------------|-----------------------------------|
| Одна запись в 0Ch                           | Цвет может не установиться           | Писать 4–8 раз подряд             |
| Менять палитру без синхронизации с лучом    | Артефакты, мерцание                  | Либо VBlank, либо точный тайминг  |
| Путать формат цвета (думают 6 бит)          | Неправильные оттенки                 | RRR GGG BB (3+3+2)                |
| Забыть выставить номер ячейки в порт 02h    | Пишется не туда                      | Сначала OUT 02h, потом OUT 0Ch    |
| Думать, что палитра «железной» защищена     | Можно испортить изображение          | Всегда можно перезаписать         |

#### 5.4.7. Пример минимальной таблицы цветов

```asm
; Пример: чёрный, синий, зелёный, циан, красный… белый + бордюр
Palette:
        DB  00h     ; 0  чёрный
        DB  01h     ; 1  тёмно-синий
        DB  08h     ; 2  тёмно-зелёный
        DB  09h     ; 3  тёмно-циан
        DB  40h     ; 4  тёмно-красный
        DB  41h     ; 5  пурпурный
        DB  48h     ; 6  коричневый
        DB  49h     ; 7  серый
        DB  07h     ; 8  ярко-синий
        DB  38h     ; 9  ярко-зелёный
        DB  3Fh     ; 10 ярко-циан
        DB 0C0h     ; 11 ярко-красный
        DB 0C7h     ; 12 ярко-пурпурный
        DB 0F8h     ; 13 жёлтый
        DB 0FFh     ; 14 белый
        DB 0FFh     ; 15 бордюр (белый)
```

### 5.5. Звук — КР580ВИ53 (полная документация)

#### 5.5.1. Аппаратная часть

На Векторе-06Ц звук генерируется микросхемой **КР580ВИ53** (клон Intel 8253).

| Параметр                    | Значение                          |
|-----------------------------|-----------------------------------|
| Количество каналов          | **3** (только тональные)          |
| Форма волны                 | Прямоугольник (меандр, 50 %)      |
| Тактовая частота на входе   | **1 500 000 Гц** (1.5 МГц)        |
| Регулировка громкости       | Нет (только вкл/выкл канала)      |
| Аппаратный шумовой канал    | **Отсутствует**                   |
| Выход                       | Резисторный смеситель → динамик + линейный выход на магнитофон |

> «+1 шумовой канал», о котором часто пишут, — это либо программный шум (через бипер/магнитофонный порт), либо внешний AY-3-8910.

#### 5.5.2. Порты ВИ53

| Порт  | Назначение                          |
|-------|-------------------------------------|
| **08h** | Регистр управляющего слова (Control Word) |
| **0Bh** | Счётчик канала 0                    |
| **0Ah** | Счётчик канала 1                    |
| **09h** | Счётчик канала 2                    |

#### 5.5.3. Управляющее слово (порт 08h)

Формат байта:

```
D7 D6 | D5 D4 | D3 D2 D1 | D0
 SC1 SC0 | RL1 RL0 | M2 M1 M0 | BCD
```

| Поле     | Значение для звука                          |
|----------|---------------------------------------------|
| SC1 SC0  | 00 = канал 0, 01 = канал 1, 10 = канал 2   |
| RL1 RL0  | 11 = сначала младший байт, потом старший   |
| M2 M1 M0 | **011** = режим 3 (генератор меандра)      |
| BCD      | 0 = двоичный счёт                          |

Готовые значения для режима 3:

| Канал | Управляющее слово |
|-------|-------------------|
| 0     | **36h**           |
| 1     | **76h**           |
| 2     | **B6h**           |

#### 5.5.4. Формула частоты

```
делитель = 1 500 000 / частота_в_Гц
```

Примеры:

| Частота | Делитель (dec) | Делитель (hex) |
|---------|----------------|----------------|
| 440 Гц (ля) | 3409        | 0D51h          |
| 1000 Гц     | 1500        | 05DCh          |
| 2000 Гц     | 750         | 02EEh          |
| 3000 Гц     | 500         | 01F4h          |

#### 5.5.5. Включение канала (пример)

```asm
; Включить канал 0 на 1000 Гц
        MVI  A,36h          ; канал 0, режим 3, LSB+MSB
        OUT  08h
        MVI  A,0DCh         ; младший байт делителя 1500
        OUT  0Bh
        MVI  A,05h          ; старший байт
        OUT  0Bh
```

#### 5.5.6. Классический пример трёхголосного звука
(из «Секретов Вектора» Лебедева А.З., 1992)

```asm
Sound0: DW   1500           ; 1000 Гц
Sound1: DW   0750           ; 2000 Гц
Sound2: DW   0500           ; 3000 Гц

; Включение канала 0
Voice0: MVI  A,36h
        OUT  08h
        LHLD Sound0
        MOV  A,L
        OUT  0Bh
        MOV  A,H
        OUT  0Bh

; Включение канала 1
Voice1: MVI  A,76h
        OUT  08h
        LHLD Sound1
        MOV  A,L
        OUT  0Ah
        MOV  A,H
        OUT  0Ah

; Включение канала 2
Voice2: MVI  A,0B6h
        OUT  08h
        LHLD Sound2
        MOV  A,L
        OUT  09h
        MOV  A,H
        OUT  09h
```

#### 5.5.7. Выключение каналов

Чтобы полностью выключить канал, достаточно снова записать управляющее слово (режим 3), **не загружая** счётчик, или загрузить очень большое значение.  
Самый распространённый способ в играх:

```asm
; Выключить канал 2
        MVI  A,0B6h
        OUT  08h
        ; счётчик не загружаем — канал замолкает
```

Или явно:

```asm
        MVI  A,0B6h
        OUT  08h
        MVI  A,00h          ; делитель = 0 (или очень большой)
        OUT  09h
        OUT  09h
```

#### 5.5.8. Программный «шумовой» канал (4-й) — подробная документация

**Важно:** на штатном КР580ВИ53 **аппаратного шумового канала нет**.  
Всё, что называют «4-м каналом» или «шумом», реализуется программно.

Существует два основных способа получить шумовые эффекты:

---

##### Способ 1. Псевдо-шум через быстрое изменение частоты канала ВИ53

Самый распространённый метод в играх. Один из каналов (обычно 2-й) быстро «дёргают» по частоте.

**Простейший взрыв / выстрел:**

```asm
; Короткий шумовой эффект на канале 2
NoiseShot:
        MVI  A,0B6h         ; канал 2, режим 3
        OUT  08h
        MVI  B,30h          ; длительность эффекта
NShot1: MOV  A,B
        OUT  09h            ; младший байт делителя
        OUT  09h
        DCR  B
        JNZ  NShot1
        ; выключить канал
        MVI  A,0B6h
        OUT  08h
        RET
```

**Шум с псевдо-случайным делителем:**

```asm
NoiseRandom:
        MVI  A,0B6h
        OUT  08h
        MVI  B,40h
NRand:  LDA  NoiseSeed
        ADD  A
        ADI  17h
        STA  NoiseSeed
        OUT  09h
        OUT  09h
        DCR  B
        JNZ  NRand
        MVI  A,0B6h
        OUT  08h
        RET

NoiseSeed: DB 0A5h
```

**Шум с затуханием (для взрывов):**

```asm
NoiseExplode:
        MVI  A,0B6h
        OUT  08h
        MVI  B,80h          ; начальный делитель (высокая частота)
NExpl:  MOV  A,B
        OUT  09h
        OUT  09h
        MVI  C,08h
NDel:   DCR  C
        JNZ  NDel
        INR  B
        INR  B
        MOV  A,B
        CPI  0F0h
        JC   NExpl
        MVI  A,0B6h
        OUT  08h
        RET
```

---

##### Способ 2. 1-bit бипер через порт 01h

```asm
BeepNoise:
        MVI  B,40h
BNLoop: MVI  A,08h
        OUT  01h
        MVI  C,10h
BNDel1: DCR  C
        JNZ  BNDel1
        XRA  A
        OUT  01h
        MVI  C,10h
BNDel2: DCR  C
        JNZ  BNDel2
        DCR  B
        JNZ  BNLoop
        RET
```

> В современных играх почти всегда используют **Способ 1** (изменение делителя ВИ53).

##### Рекомендации

| Задача              | Способ                        | Канал |
|---------------------|-------------------------------|-------|
| Выстрел, удар       | Быстрое изменение делителя    | 2     |
| Взрыв               | Затухающий шум                | 2     |
| Шаги, шум мотора    | Случайное изменение           | 2     |
| Короткий «клик»     | 1-bit бипер                   | —     |
| Музыка              | Обычные тона                  | 0 + 1 |

#### 5.5.9. Современный подход (как в OldTower и demoscene)

- Музыка пишется в **Vortex Tracker II**.
- Конвертируется специальным плеером `vt2vi53` (Denis Grachev) в формат под 2–3 канала ВИ53.
- Звуковые эффекты делаются в **AYFX Editor**, затем конвертируются в последовательность делителей + команды вкл/выкл.
- Всё обновляется в обработчике прерывания 50 Гц.

Типичное распределение в играх:
- Каналы 0 и 1 — музыка
- Канал 2 — звуковые эффекты (SFX)

#### 5.5.10. Типичные ошибки нейросетей и начинающих

| Ошибка                                      | Почему плохо                              | Как правильно                     |
|---------------------------------------------|-------------------------------------------|-----------------------------------|
| Пишут «4 канала» / «шум есть»               | На штатном ВИ53 шума нет                  | 3 тона + программный шум          |
| Забывают записывать управляющее слово       | Канал не запускается                      | Сначала OUT 08h, потом счётчик    |
| Путают порты каналов (09/0A/0B)             | Звук идёт не туда                         | 0 = 0Bh, 1 = 0Ah, 2 = 09h         |
| Используют частоту 3 МГц вместо 1.5 МГц     | Ноты вдвое выше                           | делитель = 1500000 / freq         |
| Не выключают каналы при окончании эффекта   | Звук «висит»                              | Повторно писать управляющее слово |
| Пытаются менять громкость через ВИ53        | Невозможно                                | Только вкл/выкл                   |

## 6. Канонические вспомогательные процедуры

Эти короткие процедуры предназначены как готовые шаблоны для AI и программистов.  
Их можно копировать почти без изменений.

### 6.1. Ожидание кадрового прерывания (WaitVBlank)

Самый простой и надёжный способ — поставить флаг в обработчике прерывания.

```asm
; В обработчике прерывания:
IntHandler:
        PUSH PSW
        MVI  A,1
        STA  VBlankFlag
        ; ... остальная обработка
        POP  PSW
        EI
        RET

VBlankFlag: DB 0

; В основном коде:
WaitVBlank:
        XRA  A
        STA  VBlankFlag
WaitLoop:
        LDA  VBlankFlag
        ORA  A
        JZ   WaitLoop
        RET
```

### 6.2. Проверка нажатия клавиши (IsKeyPressed)

Пример проверки одной конкретной клавиши (здесь — курсор «вверх», строка 0, бит 5).

```asm
; Возвращает: Z=1 — не нажата, Z=0 — нажата
IsKeyUp:
        MVI  A,0FEh         ; строка 0
        OUT  03h
        IN   02h
        ANI  20h            ; бит 5 (↑)
        RET                 ; Z=1 если не нажата
```

Для проверки нескольких клавиш удобнее один раз просканировать нужные строки и работать с буфером.

### 6.3. Очистка экрана (ClearScreen) — одна плоскость

```asm
; Очистить плоскость 3 (8000h–9FFFh) нулями
ClearPlane3:
        LXI  H,8000h
        LXI  B,2000h        ; 8 КБ
ClrLoop:
        MVI  M,00h
        INX  H
        DCX  B
        MOV  A,B
        ORA  C
        JNZ  ClrLoop
        RET
```

Для полной очистки 16-цветного экрана нужно очистить все четыре плоскости (8000, A000, C000, E000).

### 6.4. Установка палитры (SetPalette)

(уже есть подробный вариант в разделе 5.4 — используйте его)

Краткий вариант:

```asm
; HL → таблица 16 байт (COLR0…COLR15)
SetPalette:
        MVI  E,0Fh
        MVI  D,16
SPLoop: MOV  A,E
        OUT  02h
        MOV  A,M
        OUT  0Ch
        OUT  0Ch
        OUT  0Ch
        OUT  0Ch
        DCX  H
        DCR  E
        DCR  D
        JNZ  SPLoop
        RET
```

### 6.5. Проиграть ноту (PlayTone)

```asm
; Проиграть частоту на канале 0
; DE = делитель (1500000 / freq)
PlayTone0:
        MVI  A,36h          ; канал 0, режим 3
        OUT  08h
        MOV  A,E
        OUT  0Bh
        MOV  A,D
        OUT  0Bh
        RET

; Выключить канал 0
MuteTone0:
        MVI  A,36h
        OUT  08h
        RET
```

### 6.6. Минимальный обработчик прерывания

```asm
IntHandler:
        PUSH PSW
        PUSH B
        PUSH D
        PUSH H
        ; — обновление музыки
        ; — опрос клавиатуры
        ; — таймеры игры
        ; — установка флага VBlank
        POP  H
        POP  D
        POP  B
        POP  PSW
        EI
        RET
```

## 7. Прерывания

- Единственное аппаратное прерывание — **кадровое** (VBlank), 50 Гц.
- Вызывается как **RST 7** → переход на адрес **0038h**.
- В обработчике **обязательно** сохранять все используемые регистры.

Пример минимального обработчика:

```asm
IntHandler:
        PUSH PSW
        PUSH B
        PUSH D
        PUSH H
        ; ... ваша обработка (обновление экрана, звук и т.д.)
        POP  H
        POP  D
        POP  B
        POP  PSW
        EI
        RET
```

**Важно:** после `EI` прерывание разрешается только после следующей команды.

## 8. Особенности таймингов на Векторе

Из-за видеоконтроллера машинные циклы растягиваются:

| Тип команды          | Чистый 8080 | Вектор-06Ц (примерно) |
|----------------------|-------------|-----------------------|
| 4-тактовые           | 4           | 4                     |
| 5-тактовые           | 5           | 8                     |
| 7-тактовые           | 7           | 8                     |
| 10-тактовые          | 10          | 12                    |
| MOV r,r              | 5           | **8**                 |
| MVI r,d              | 7           | **8**                 |
| ADD r                | 4           | **4**                 |
| CALL                 | 17          | **24**                |

Для точного программирования игр/демо используйте таблицы таймингов из emuverse / github.com/svofski.

## 9. Рекомендации по написанию кода (чтобы не ошибаться)

1. **Всегда** начинайте программу с установки векторов 0000h и 0038h.
2. **Всегда** отключайте квазидиск (`OUT 10h,0`), если программа должна работать на машинах без него.
3. Стек ставьте в безопасную область (например, `LXI SP,53FFh` при работе из монитора).
4. Не используйте недокументированные команды без необходимости.
5. Для палитры и клавиатуры строго соблюдайте порядок работы с портами 02h/03h/0Ch.
6. В обработчике прерывания сохраняйте **все** регистры, которые используете.
7. Не забывайте `EI` после `DI` (и наоборот).
8. При портировании с Z80 помните: нет IX/IY, нет относительных переходов, нет блочных команд.

## 11. Структура ROM и организация памяти (для программиста)

### 10.1. Формат файла .ROM

```
Файл .ROM:
- Первый байт файла загружается по адресу 0100h
- Размер файла = количество загружаемых байт
- После загрузки PC устанавливается в 0100h
```

`ORG 0100h` в исходнике — это адрес размещения, **а не** заголовок файла.

### 10.2. Рекомендуемая карта памяти программы

```
0000h–00FFh   — векторы (программа сама прописывает JMP)
0100h         — точка входа (Start)
0100h–...     — код
...           — таблицы, данные, константы
...           — буферы (спрайты, экранные области и т.п.)
...           — стек (растёт вниз)
8000h–FFFFh   — видеопамять (в зависимости от режима)
```

### 10.3. Безопасное размещение стека

```asm
        LXI  SP,StackTop
        ...
Stack:  DS   128            ; или больше, если нужно
StackTop:
```

**Нельзя** ставить `LXI SP,0FFFFh` — можно затереть важные данные или выйти за пределы доступной памяти.  
Выбирайте область **выше** кода и данных, но **ниже** видеопамяти (или в свободной зоне).

### 10.4. Минимальный правильный шаблон ROM

```asm
        ORG  0100h

Start:  DI
        LXI  SP,StackTop
        MVI  A,0C3h         ; JMP
        STA  0000h
        STA  0038h
        LXI  H,Main
        SHLD 0001h
        LXI  H,IntHandler
        SHLD 0039h
        XRA  A
        OUT  10h            ; отключить квазидиск
        ; инициализация ВВ55, палитры, звука...
        EI
        JMP  Main

Main:   ; основной цикл
        JMP  Main

IntHandler:
        PUSH PSW
        PUSH B
        PUSH D
        PUSH H
        ; обновление звука, клавиатуры, таймеров...
        POP  H
        POP  D
        POP  B
        POP  PSW
        EI
        RET

        DS   128
StackTop:
```

## 12. Ограничения КР580ВМ80А по сравнению с Z80

**Запрещено** генерировать любые Z80-инструкции, даже если они синтаксически похожи.

| Z80              | Эквивалент на 8080 / КР580ВМ80А          |
|------------------|------------------------------------------|
| JR  addr         | JMP addr                                 |
| JR  Z/NZ/...     | JZ / JNZ / ...                           |
| DJNZ             | DCR B + JNZ  (или DCR C)                 |
| LDIR             | цикл: MOV M,A / INX H / INX D / DCR B... |
| LD  BC,nn        | LXI B,nn                                 |
| LD  A,(nn)       | LDA nn                                   |
| LD  (nn),A       | STA nn                                   |
| LD  (HL),A       | MOV M,A                                  |
| ADD A,(HL)       | ADD M                                    |
| IX / IY          | **нет** (использовать HL + смещение вручную) |
| EX  AF,AF'       | **нет**                                  |
| EXX              | **нет**                                  |
