# PSP Build System Documentation

## Overview

The PSP port uses a standard Makefile-based build system with support for multiple build configurations and automatic deployment to the PPSSPP emulator.

## Build Configurations

### Build Flags

- **DEBUG_ENABLED** (default: 1)
  - `1` — Debug build: `-O2`, debug logging enabled
  - `0` — Release build: `-O3`, no debug logging

- **PROFILE** (default: 0)
  - `1` — Profiler build: `-O2 -pg`, generates `gmon.out` for gprof analysis
  - Requires `DEBUG_ENABLED=0` for accurate profiling

- **EXTRA_DEFS** — Additional preprocessor definitions (e.g., `-DAUTOSELECT_ROM`)

### Optimization Levels

- Debug builds (`DEBUG_ENABLED=1`): `-O2` (required for stable debugging)
- Release builds (`DEBUG_ENABLED=0`): `-O3` (maximum performance)
- Profile builds (`PROFILE=1`): `-O2` (profiler stability; `-O3` crashes)

## Build Targets

### Standard Targets

#### `make` or `make all`
Build the default configuration (debug) and copy `EBOOT.PBP` to `boot/`.

```bash
make                    # Debug build
make DEBUG_ENABLED=0    # Release build
```

#### `make clean`
Remove all build artifacts including `boot/EBOOT.PBP`, `gmon.out`, and `profile.txt`.

### Deploy Targets

Deploy targets build the project and automatically copy `EBOOT.PBP` to the PPSSPP game directory:
```
~/snap/ppsspp-emu/common/.config/ppsspp/PSP/GAME/VECTOR06C/EBOOT.PBP
```

#### `make deploy`
Alias for `deploy-release` (default deployment).

#### `make deploy-debug`
Debug build + deploy.

```bash
make deploy-debug
```

Equivalent to:
```bash
make DEBUG_ENABLED=1
cp boot/EBOOT.PBP ~/snap/ppsspp-emu/common/.config/ppsspp/PSP/GAME/VECTOR06C/
```

#### `make deploy-release`
Release build + deploy (optimized, no debug logging).

```bash
make deploy-release
```

#### `make deploy-autoselect`
Release build with `AUTOSELECT_ROM` test hook + deploy.

```bash
make deploy-autoselect
```

The autoselect build boots directly into a ROM specified by `autoselect.txt` (index into `ROMS/` directory), bypassing the ROM browser. Useful for automated testing and profiling.

#### `make deploy-profile`
Profiler build + deploy (`PROFILE=1`, `DEBUG_ENABLED=0`, `-O2 -pg`).

```bash
make deploy-profile
```

Generates `gmon.out` in the game directory after execution. Analyze with `utils/analyze_profile`.

## Build Variables

### PPSSPP_DIR
Destination directory for deployment:
```makefile
PPSSPP_DIR = $(HOME)/snap/ppsspp-emu/common/.config/ppsspp/PSP/GAME/VECTOR06C
```

Override if your PPSSPP installation is in a different location:
```bash
make deploy-release PPSSPP_DIR=/custom/path/to/VECTOR06C
```

## Build Artifacts

- `v06xpsp.elf` — Linked ELF executable
- `EBOOT.PBP` — PSP executable package
- `boot/EBOOT.PBP` — Local copy of the executable
- `gmon.out` — Profiler output (PROFILE builds only)
- `profile.txt` — Human-readable profile analysis (generated by `utils/analyze_profile`)

## Examples

### Quick Development Cycle

```bash
# Build and deploy debug version
make deploy-debug

# Launch PPSSPP manually or use utils/run_60sec_kill
```

### Release Testing

```bash
# Build and deploy release version
make deploy-release

# Run for 60 seconds and collect perf.log
./utils/run_60sec_kill
```

### Performance Profiling

```bash
# Build with profiler
make deploy-profile

# Run for 60 seconds (generates gmon.out)
./utils/run_60sec_kill

# Analyze profile
./utils/analyze_profile

# View results
less profile.txt
```

### Automated Sound Mode Testing

```bash
# Test all sound modes (none/cubic/gaussian/sinc)
./utils/sweep_sound_modes.sh

# Test with WAV recording (debug build required)
cd psp
make deploy-debug
RECORD=1 ./utils/sweep_sound_modes.sh
```

## Notes

- Header dependency tracking is not implemented. After modifying header files, run `make clean` before rebuilding.
- Profile builds use `-O2` instead of `-O3` because `-pg` combined with `-O3` causes crashes on the PSP toolchain.
- The `AUTOSELECT_ROM` build hook stops execution after 60 seconds and exits cleanly, useful for automated benchmarking.
