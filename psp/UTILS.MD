# PSP Utility Scripts Documentation

## Overview

The `utils/` directory contains helper scripts for building, testing, profiling, and analyzing the PSP port. All scripts should be run from the `psp/` directory unless otherwise noted.

## Build & Deploy Utilities

These utilities are now integrated into the Makefile as deploy targets. See `MAKEFILE.MD` for details.

- `make deploy-debug` — Debug build + deploy
- `make deploy-release` — Release build + deploy
- `make deploy-autoselect` — Autoselect ROM build + deploy
- `make deploy-profile` — Profiler build + deploy

## Profiling Utilities

### analyze_profile

Analyze gprof profiling data from a PROFILE build.

**Usage:**
```bash
./utils/analyze_profile
```

**Prerequisites:**
1. Build with profiler: `make deploy-profile`
2. Run the emulator: `./utils/run_60sec_kill`
3. This generates `gmon.out` in the game directory

**Output:**
- `profile.txt` — Human-readable gprof flat profile and call graph

**Example:**
```bash
# Build with profiler
make deploy-profile

# Run for 60 seconds
./utils/run_60sec_kill

# Analyze results
./utils/analyze_profile

# View the profile
less profile.txt
```

**Notes:**
- Must be run from the `psp/` directory (looks for `v06xpsp.elf` and `gmon.out`)
- Requires `psp-gprof` from the PSP toolchain

### run_60sec_kill

Run PPSSPP emulator for 65 seconds and terminate it automatically.

**Usage:**
```bash
./utils/run_60sec_kill [ppsspp-log]
```

**Parameters:**
- `ppsspp-log` — Optional path for PPSSPP log file (default: `<game dir>/ppsspp.log`)

**Purpose:**
- Automated testing and profiling
- The emulator runs for 65 seconds (60s for the emulator + 5s for cleanup)
- AUTOSELECT builds stop after 60s and flush their logs before exiting

**Output (in game directory):**
- `perf.log` — Per-second performance breakdown (AUTOSELECT builds only)
- `gmon.out` — gprof profiling data (PROFILE builds only)
- `ppsspp.log` — PPSSPP emulator log

**Example:**
```bash
# Deploy autoselect build
make deploy-autoselect

# Run for 60 seconds
./utils/run_60sec_kill

# Check results
ls -l ~/snap/ppsspp-emu/common/.config/ppsspp/PSP/GAME/VECTOR06C/perf.log
```

**Notes:**
- Requires PPSSPP snap package installed at `/snap/bin/ppsspp-emu.ppsspp-sdl`
- Uses `setsid` to create a new process group for clean termination
- Sends SIGTERM, waits 2 seconds, then SIGKILL if needed

## Testing Utilities

### sweep_sound_modes.sh

Automated testing of all sound interpolation modes (none/cubic/gaussian/sinc).

**Usage:**
```bash
./utils/sweep_sound_modes.sh              # Performance test (release)
RECORD=1 ./utils/sweep_sound_modes.sh     # Test with WAV recording (debug)
```

**Purpose:**
- Tests each sound mode for 60 seconds
- Collects performance metrics and optional audio recordings
- Useful for comparing CPU usage and audio quality across modes

**Prerequisites:**
- For performance testing: `make deploy-autoselect`
- For WAV recording: `make deploy-debug` (debug build with `sound_record = true`)

**Process:**
For each mode (none, cubic, gaussian, sinc):
1. Write `config.ini` with the sound mode
2. Run `run_60sec_kill` (65 seconds)
3. Collect results into `sound_mode_results/<mode>/`

**Output (in `sound_mode_results/<mode>/`):**
- `perf.log` — Performance metrics (FPS, CPU usage, timing)
- `debug.log` — Sound callback statistics (debug builds only)
- `psp_internal.wav` — Generated audio before PSP output (RECORD=1 only)
- `psp_callback.wav` — Audio sent to PSP hardware (RECORD=1 only)

**Example:**
```bash
# Performance comparison
make deploy-autoselect
./utils/sweep_sound_modes.sh

# Audio quality comparison
make deploy-debug
RECORD=1 ./utils/sweep_sound_modes.sh

# View results
ls -l sound_mode_results/
```

**Configuration:**
The script writes `config.ini` for each test with:
```ini
border = true
fps = true
fast_framebuffer = true
worker_priority = 0x30
main_priority = 0x18
sound_mode = <mode>
```

With `RECORD=1`, it also adds:
```ini
sound_record = true
```

**Notes:**
- Each mode takes ~65 seconds to test (total: ~4.5 minutes)
- Old results are overwritten (not appended)
- WAV files are only generated with debug builds and `RECORD=1`

## Common Workflows

### Performance Profiling

```bash
# 1. Build with profiler
make deploy-profile

# 2. Run for 60 seconds
./utils/run_60sec_kill

# 3. Analyze profile
./utils/analyze_profile

# 4. View results
less profile.txt
```

### Sound Mode Benchmark

```bash
# 1. Build autoselect version
make deploy-autoselect

# 2. Test all modes
./utils/sweep_sound_modes.sh

# 3. Compare results
for mode in none cubic gaussian sinc; do
    echo "=== $mode ==="
    tail -5 sound_mode_results/$mode/perf.log
done
```

### Audio Quality Testing

```bash
# 1. Build debug version with recording
make deploy-debug

# 2. Record audio for each mode
RECORD=1 ./utils/sweep_sound_modes.sh

# 3. Listen to recordings
aplay sound_mode_results/sinc/psp_callback.wav
```

## Troubleshooting

### "gmon.out not found"
- Ensure you built with `make deploy-profile`
- Check that `run_60sec_kill` completed successfully
- Verify PPSSPP ran for the full 65 seconds

### "PPSSPP not found"
- Install PPSSPP snap: `sudo snap install ppsspp-emu`
- Or update the path in `run_60sec_kill`:
  ```bash
  PPSSPP="/your/path/to/ppsspp"
  ```

### "Permission denied" for scripts
```bash
chmod +x utils/*
```

### Profile analysis shows no data
- Profile builds use `-O2` instead of `-O3` for stability
- Some functions may be inlined and not appear in the profile
- Check that the emulator actually ran (look for `perf.log`)
